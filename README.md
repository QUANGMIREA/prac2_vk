# Задача № 2. Анализ центральности в социальной сети ВКонтакте

Практическая работа по дисциплине «Интеллектуальные системы и технологии».

## Цель работы

Построить граф связей между участниками учебной группы, их друзьями и друзьями друзей во ВКонтакте. На основе полученного графа вычислить для участников группы три показателя центральности:

- центральность по посредничеству (*betweenness centrality*);
- центральность по близости (*closeness centrality*);
- центральность по собственному вектору (*eigenvector centrality*).

Показатели рассчитываются с учётом всех вершин наблюдаемой сети. В итоговую таблицу включаются только участники учебной группы.

## Исходные данные

Данные о дружеских связях представлены в виде неориентированного графа \(G=(V,E)\), где вершина соответствует аккаунту ВКонтакте, а ребро — установленной связи дружбы между двумя аккаунтами.

Для подготовки данных используются три CSV-файла в кодировке UTF-8:

| Файл | Содержание |
| --- | --- |
| `members.csv` | Идентификаторы и имена участников учебной группы |
| `other_users.csv` | Идентификаторы и имена пользователей вне учебной группы; нужны для подписей на графе |
| `edges.csv` | Пары идентификаторов пользователей, между которыми установлена связь дружбы |

Пример `members.csv`:

```csv
vk_id,name
student_a,Участник А
student_b,Участник Б
```

Пример `other_users.csv`:

```csv
vk_id,name
friend_c,Пользователь В
```

Пример `edges.csv`:

```csv
source,target
student_a,student_b
student_a,friend_c
student_b,friend_c
```

Примеры выше служат только для иллюстрации формата. При выполнении работы файлы заполняются проверенными сведениями о связях. Один и тот же аккаунт должен иметь одинаковый идентификатор во всех файлах. Поскольку граф неориентированный, связи `A,B` и `B,A` эквивалентны.

Сведения о дружбе могут быть неполными из-за настроек приватности и ограничений доступа к спискам друзей. Поэтому результаты характеризуют **наблюдаемую часть сети**, а не всю социальную сеть ВКонтакте.

## Методика расчёта

Для анализа применяется библиотека `NetworkX`.

### Центральность по посредничеству

Показывает, насколько часто вершина располагается на кратчайших путях между другими вершинами:

\[
C_B(v)=\sum_{s \ne v \ne t}\frac{\sigma_{st}(v)}{\sigma_{st}},
\]

где \(\sigma_{st}\) — число кратчайших путей между \(s\) и \(t\), а \(\sigma_{st}(v)\) — число таких путей, проходящих через \(v\). В программе применяется нормализованная оценка `nx.betweenness_centrality()`.

### Центральность по близости

Характеризует среднюю доступность остальных вершин по кратчайшим путям. Для связного графа:

\[
C_C(v)=\frac{|V|-1}{\sum_{u\ne v}d(v,u)}.
\]

Используется `nx.closeness_centrality()` с параметром `wf_improved=True`, который учитывает размер достижимой части сети при наличии нескольких компонент связности.

### Центральность по собственному вектору

Учитывает не только количество связей вершины, но и центральность соседних вершин:

\[
Ax=\lambda x,
\]

где \(A\) — матрица смежности графа, \(x\) — собственный вектор центральностей. Для каждой компоненты связности значения вычисляются отдельно функцией `nx.eigenvector_centrality()`. **Значения, полученные для разных компонент, не следует напрямую сравнивать.** Изолированным вершинам присваивается значение 0.

## Структура проекта

```text
vk_centrality_task2/
├── main.py
├── members.csv
├── other_users.csv
├── edges.csv
├── requirements.txt
├── test_main.py
├── README.md
└── output/                  # создаётся после запуска
    ├── centrality_results.csv
    ├── network.png
    └── centrality_chart.png
```

Файлы `members.csv` и `other_users.csv` содержат имена для вывода и визуализации. При построении графа учитываются только связи из `edges.csv`; отсутствующие там пользователи из `other_users.csv` не добавляются как отдельные вершины. Участники группы из `members.csv` сохраняются в графе даже при отсутствии зафиксированных связей.

## Запуск

Необходим Python 3.10 или новее.

1. Открыть каталог проекта в терминале.
2. Установить зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Проверить содержимое `members.csv`, `other_users.csv` и `edges.csv`.
4. Выполнить расчёт:

   ```bash
   python main.py
   ```

При необходимости можно указать собственные пути к файлам:

```bash
python main.py --members members.csv --other-users other_users.csv --edges edges.csv --out output
```

Для запуска имеющихся модульных тестов:

```bash
python -m unittest -v
```

## Результаты работы программы

После выполнения создаются следующие файлы:

- `output/centrality_results.csv` — идентификатор, имя, степень вершины и три показателя центральности для участников группы;
- `output/network.png` — изображение графа дружеских связей: **оранжевые вершины** обозначают участников группы, **зелёные** — остальных пользователей;
- `output/centrality_chart.png` — диаграммы трёх показателей центральности для участников группы.

Вершины вне группы получают подпись из `other_users.csv`. Если имя для вершины отсутствует, на рисунке отображается её идентификатор. Сведения о пользователях из `other_users.csv` не включаются в итоговую таблицу показателей группы.

В терминале также выводятся число вершин и рёбер, число компонент связности и значения центральностей. Конкретные результаты зависят от загруженных CSV-файлов.

## Ограничения и интерпретация

Рассчитанные показатели характеризуют структуру собранного графа и могут измениться при добавлении новых связей. В частности, отсутствие доступного списка друзей не означает отсутствие дружеских связей у пользователя. Сравнение результатов следует проводить с учётом полноты исходных данных и компонент связности графа.

При публикации репозитория необходимо убедиться, что сведения о третьих лицах разрешено распространять. При необходимости идентификаторы и имена заменяются согласованными псевдонимами, а исходные персональные данные не публикуются.
